# 提取任务说明书（给大模型的作业要求）

> 把本说明书连同 PDF 一起交给大模型。**输出必须是严格的 JSON**，我们会自动入库校验，格式不对 = 白干。

## 任务 A：定期报告运营/财务字段（适用清单里大部分年报/季报）

**必抽字段**（按报告类型取舍，找不到填 null，禁止编造）：
- 财务类：营业收入、EBITDA、净利润、可供分配金额、现金流分派率（注明当期/年化口径）、期末基金规模、资产负债率
- 产权类（产业园/仓储/保租房/消费）：各底层项目的出租率、租金单价（元/㎡/月）、收缴率、**WALT 加权剩余租期（年）**、续租率
- 特许类（高速/能源/水务）：各项目的**剩余收费年限（年）**、日均车流量、利用小时、上网电价、处理量
- 消费类：各项目的销售额、客流、租售比、坪效

**输出格式**（严格 JSON，一个字段都不能少结构）：
```json
{
  "fields": [
    {"name": "项目名-指标名", "value": 98.5, "unit": "%", "period": "2024A", "page": 35}
  ]
}
```
**硬性要求**：
1. `page` 必须是该数字实际所在的 PDF 页码（物理页序，从 1 计）。没有页码的字段一律填 null——无页码的数据对我们没有价值
2. `name` 用「项目名-指标名」格式（如「汉孝高速-剩余收费年限」「杭州泰华城-WALT」）
3. value 只填数字（可带负号），单位放 unit；「13.14亿元」→ value: 13.14, unit: "亿元"
4. 同一指标出现在多期，按报告期分行输出

## 任务 B：招募书核心信息（适用招募说明书）

输出 JSON：
```json
{
  "basic": {"raise_size": {"value": 20.45, "unit": "亿元", "page_no": 29},
            "fund_term": {"value": 27, "unit": "年", "page_no": 29},
            "offering_price": {"value": null, "unit": "元", "page_no": null},
            "total_shares": {"value": null, "unit": "亿份", "page_no": null},
            "original_owner": {"value": "原始权益人及战配比例描述", "page_no": 30},
            "strategic_ratio": {"value": "不低于40%", "page_no": 30}},
  "assets": [{"name": {"value": "项目全名", "page_no": 30},
              "location": {"value": "所在地", "page_no": 30},
              "appraisal_value": {"value": 12.3, "unit": "亿元", "page_no": 31},
              "land_tenure": {"value": "土地剩余年限", "page_no": 31}}],
  "extras": [{"key": "其他要点", "value": "内容", "page_no": 页码}]
}
```

## 我们的校验规则（提醒：别试图绕过）

1. 数值与我们库内已有值偏差 >5% 的，标记人工复核（不是拒绝，但要说明）
2. 页码超过 PDF 总页数、或页码页文本抽查对不上值的，整条废弃
3. 字段名会自动归一化（不区分全半角/括号），但「项目名-指标名」的项目名要跟报告原文一致

## 优先级建议（如果模型有页数/时长限制，按此顺序抽）

1. WALT / 续租率（全库最缺，只有年报披露）
2. 剩余收费年限（特许类估值核心）
3. 消费类销售额/客流/租售比
4. 常规财务四件套（我们已有大部分，仅补缺）
